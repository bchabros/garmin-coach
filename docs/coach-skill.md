Reads the mart,applies the rules below, renders two charts, writes a Polish report.> This is a **read + reason** skill. Never call the Garmin MCP or `garminconnect`> from here. If data is stale, invoke the ETL (`garmin-coach sync && features`);> if it can't run, report on what's in the DB and note the staleness.## When to useWeekly review, "how's my training going", load-balance / ACWR / HRV / sleep /overtraining questions, plan-vs-actual checks. For a single-day "should I traintoday?" answer, read today's `training_readiness` + `daily_metrics` and applyrules 3–4 only.## Prerequisites- DB at `$GARMIN_DB` (default `./data/garmin.db`). Confirm it exists; if not, tell  the user to run the ETL backfill first.- Freshness: if `MAX(date)` in `daily_metrics` is older than yesterday, run  `garmin-coach sync && garmin-coach features` before analysing. TODO(claude-code):  wire this via `scripts/build_report.py`.## What it reads (nothing else)- Marts: `daily_metrics`, `weekly_metrics`- Views: `v_daily`, `v_flags`, `v_activity_enriched`- Core (for detail): `activities`, `activity_sets`, `sleep`, `training_status_daily`- Config (thresholds are **data-driven — read, don't hardcode**):  `coach_thresholds`, `plan_template````sql-- thresholds -> dictSELECT key, value FROM coach_thresholds;-- last N days of the martSELECT * FROM daily_metrics WHERE date >= date('now', ?) ORDER BY date;   -- ? = '-28 days'-- weekly rollupsSELECT * FROM weekly_metrics ORDER BY week_start DESC LIMIT 6;-- flagged daysSELECT * FROM v_flags WHERE date >= date('now','-28 days');-- discipline split over the windowSELECT discipline, COUNT(*) n, ROUND(SUM(training_load)) load, ROUND(SUM(dur_s)/60) minFROM activities WHERE date >= date('now','-28 days') GROUP BY discipline ORDER BY load DESC;```## Workflow1. Resolve `$GARMIN_DB`; ensure freshness (see Prerequisites).2. Load thresholds from `coach_thresholds` into a dict; **all rule constants come   from there**, never inline literals.3. Pull last 7 + 28 days from marts and the discipline split.4. Evaluate the rules (next section). Collect only *fired* signals.5. Render the two charts with `scripts/plots.py` → `reports/{today}/`.6. Write the Polish report from the template. Lead with the 1–3 signals that   matter most; don't dump every metric.## Coaching rulesFull catalog + rationale in `references/coaching-rules.md`. Condensed, each keyedto `coach_thresholds`:1. **Intensity distribution** — from latest `training_status_daily`: if   `ml_aero_low < ml_aero_low_min` and `ml_aero_high > ml_aero_high_max` →   `AEROBIC_LOW_SHORTAGE`: "za dużo szarej strefy, dołóż Z2". (This athlete's   baseline problem — Hyrox/Crossfit/tempo crowd out easy aerobic.)2. **ACWR** — flag `acwr > acwr_risk_high` or `< acwr_risk_low`; sweet spot   `[acwr_risk_low, acwr_sweet_hi]`. **Hard gate:** if `n_chronic < acwr_min_chronic_days`,   label the value *orientacyjny* and cross-check against   `training_status_daily.garmin_acwr`. Never flag risk on an underfilled window.3. **HRV** — nights where `hrv_low_flag = 1` (i.e. `hrv < hrv_baseline - hrv_low_k_sd*hrv_sd`).   If this morning's HRV < threshold or readiness LOW/POOR → "zdegraduj dzisiejszą   sesję jakościową do easy".4. **Two hard days in a row** — consecutive days with `load_day > hard_te_load` or   `anaero_te ≥ 1` and no easy/rest buffer between them. This athlete's known risk   is the **Fri→Sat stack** (Crossfit+Hyrox → Hyrox/tempo).5. **Sleep as a driver** — correlate `hrv` vs `sleep_score` (ref window r≈0.57).   Worst HRV nights are sometimes sleep-driven, not training-driven — don't   misattribute cause. Flag `sleep_debt_h` if it accumulates.6. **Illness watch** — `illness_watch = 1` (HRV↓ & RHR↑ & resp/skin-temp↑). Surface   gently: suggest an easy day / listening to the body, not a diagnosis.7. **Monotony / strain** (weekly) — high `monotony` / `strain` (Foster) → too little   day-to-day variance; recommend contrast (truly easy easy days).8. **Plan vs actual** — join actual sessions to `plan_template` by weekday; report   `plan_adherence` and notable deviations.## OutputCharts (reuse the thread's logic — `scripts/plots.py`):- `hrv_baseline.png` — nightly HRV, baseline line, ±1 SD band, low-HRV nights marked.- `acwr.png` — ACWR over time, 0.8 / 1.5 lines, provisional region shaded where  `n_chronic < 28`, Garmin ACWR annotated as reference.Report (Polish, Markdown) — template in `references/report-template.md`:```## Podsumowanie tygodnia (DD.MM–DD.MM)- 1–3 najważniejsze sygnały (nie wszystko naraz)### Obciążenie- load total + rozbicie low/high/anaerobic (+ udziały), ACWR (+ n_chronic caveat)- rozbicie per dyscyplina### Regeneracja- HRV vs baseline (+ noce pod progiem), sen, RHR delta, readiness### Sygnały i sugestie- fired rules -> konkretne, liczbowe rekomendacje### Plan vs realizacja- adherence + odchylenia[wykresy]```## ToneConcrete, numbers first, no filler. Always close with: to jest czytanie danych,nie zalecenie medyczne/trenerskie. State the data window and any staleness.Avoid "genuinely/honestly/actually".## Companion files (TODO for Claude Code to implement)- `scripts/build_report.py` — orchestrator: freshness check → load → rules → charts  → write report.
