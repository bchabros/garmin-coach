# Domain documentation

This repository has one domain context. Read `docs/glossary.md` before exploring;
use its terms in code, issue titles and discussion. Read the relevant ADRs through
`docs/adr/README.md` before changing a boundary or behavior.

The glossary defines concepts. Specs and implementation procedures belong in issues
and guides; architecture choices and their trade-offs belong in `docs/adr/`.
Update an existing definition in place when a term is resolved. A missing term is a
question for domain modeling, not a reason to invent an unnoticed synonym.

Flag conflicts with an accepted ADR explicitly. Reopening a decision needs its
reason and consequences recorded; shortening a document does not revoke its rules.
